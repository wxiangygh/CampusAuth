本次更新解决「已经把应用设为 IPv6，流量监控里却还是 IPv4」：设置路由时程序会真的想办法把域名送上 IPv6，做不到也会明确说明原因，不再留下一条永远不生效的规则。

- **不再显示推测出来的标签**：以前点「设为 IPv6」后列表立刻变成 IPv6 直连，那只是乐观猜测。现在标签只报实测结果；意图和实测暂时不一致时显示虚线的「已设 IPv6·待重连」，说明要等应用断开旧连接、重新解析新建后才会真的换地址族，连接一旦跟上提示自动消失。
- **IPv6 探测覆盖整个命名空间**：以前只查 `example.com` 和 `www.example.com`，父域常常没有 AAAA，于是被误判成「无 IPv6」。现在会带上本机 DNS 缓存与已有规则里出现过的子域名一起探测，并逐个尝试你在 DNS 设置里配置的解析服务器；只要有一个视图给出 IPv6 地址，就按这些地址的 /32 与 /48 前缀下 IPv6 排除段。
- **自动补定向解析**：系统解析器查不到 AAAA、但某个上游 DNS 查得到时，程序会自动为该域名新建一条 DNS 绑定并在结果里提示你到 DNS 设置页下发。浏览器只有解析结果里带 AAAA 才会走 IPv6，这一步是地址族能否真正切换的关键；下发需要管理员权限，程序不会自己弹 UAC。
- **确认无 IPv6 就写回配置**：确实拿不到 AAAA 的域名会把条目降级为 IPv4 直连，并在批量应用时汇总为「N 个域名无 IPv6 已降级为 IPv4 直连」，不会再静默失败。
- **纯 IP 连接可以排除**：流量页里只有远端 IP、没有域名的连接以前点路由没有效果，现在会自动转成单 IP 排除段处理，并说明这类连接只能排除 WARP、换地址族需应用新建连接。
- **不再用 hosts 钉死 IPv6**：hosts 固定会把域名锁在单个 CDN 节点上，改为定向解析接管；需要时会自动清掉该域名已有的 hosts 条目。
- **修复 DNS 设置页两处问题**：下发时调用了 `Add-DnsClientNrptRule` 并不存在的 `-Force` 参数，导致整批规则在提权脚本里一条都写不进去；读回规则时命名空间被显示成字面量 `System.String[]`，界面因此报「已下发 0 条」。两者均已修正。

下载附件 `CampusAuth.exe` 即可使用。更新仅替换程序，同目录的账号配置、分流规则与工作流保持不变；此前被误判为「无 IPv6」的域名可以重新点一次「IPv6 直连」，现在会按整个命名空间重新探测。
